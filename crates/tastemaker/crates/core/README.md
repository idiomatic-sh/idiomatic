# idiomatic-sh-tastemaker-core

Tastemaker's core: the use cases its command line calls, the rules it places by, and the ports it reaches through.

## Domains

### answering

Reads the lint call's answer back into findings, the comparison's syntax and the imports.

### applications

Turns a placement into the lint calls of a check and their answers back into findings.

### applying

Merges the applications matched here into the rules of the lint call.

### blocks

Reads the blocks a Markdown document makes and compares them in order with its template's.

### `built_ins`

Adds the rules the lint call carries besides the placed ones: conditions, imports, comments and comparisons.

### captures

The core domain's `captures` concept: what a pattern's `{name}`s took, and text with them replaced.

### carrying

Hands ryo whole the releases whose applications are apart, each as one rule carrying its globs.

### catalog

Writes what ryo's catalog says of its relations, operators and grammar as sections of Markdown lines.

### closing

The core domain's `closing` concept: the facts placement leaves of the closed directories, and the findings of the strays the closed query decides from them: which scope each is named after.

### comments

The core domain's `comments` concept: the line comments of a file, by the kind of file it is.

### contexts

Builds what a template's content sees for a file a scope places.

### `contract_rendering`

What a placed file's template content is rendered with, and the contract the rendered content makes of the file.

### contracts

Compares a placed file with the content its template renders, declaration by declaration.

### counting

Works out what the entries of a placement count and the pairs their captures make.

### declarations

Reads the declarations a source file makes from its syntax, each named within the items that hold it.

### definitions

Loads a workspace's definitions: its rules, specs, templates and their packages.

### digests

What a list of byte strings comes to, the digest a kept file, verdict or proof is compared by.

### entries

Reads entries, counts and values as a workspace and its specs write them.

### explanations

What `explain` says, as sections of Markdown lines, from what the workspace's files and definitions hold.

### files

A place on the machine, the text of a file, and the stamps that say whether it changed.

### findings

Builds, orders and words the findings a check reports.

### globs

Writes files as the fewest globs that cover them.

### governance

Which files each placed rule governs: its answers about other files are not its findings, and a rule that reads none of the files read is idle.

### ignores

Reads a file's in-source ignores and applies them to its findings.

### `import_rows`

The core domain's `import_rows` concept: the built-in rules that read the import relations, their rows kept, and the imports read from them.

### imports

Refuses what an entry's `imports` forbids of the imports its instances make.

### `instance_params`

Gives the params of a spec their values at one of its instances.

### judging

Judges the counts and pairs a placement left waiting, once their conditions are answered.

### keyed

The declarations a keyed document makes, read from the shared keyed relations, each table of a sequence judged whole.

### linting

What a check hands the lint call and reads back: where the call is rooted, the files it reads, the queries refused and the paths of its answers.

### loading

Reads a workspace's definitions one wave at a time.

### `module_paths`

The core domain's `module_paths` concept: a module path and a module pattern, read as the matching port reads a path.

### packages

Resolves packages, their releases and the lock.

### paths

Joins, splits and compares the repository's paths.

### placement

Places a workspace's entries: each spec entry's directories become scopes.

### planning

Turns a placement into the lint calls of a check and what each of their rules is for.

### proofs

Compares what a case expected with what it found.

### reaching

Finds the files each rule entry of each scope reaches, every entry of a scope in one pass.

### reporting

The report a check makes of the lint call's answer: findings rendered and placed, ignores applied, every finding fingerprinted.

### scaffolding

Names the file an entry places at an instance and builds what its template is rendered with when the file is first written.

### scalars

The core domain's `scalars` concept: the scalar values a definition writes, text, numbers and yes or no, and the keys of its tables.

### `scenario_entries`

The keys of the entry that places what a scenario proves: a rule's include and exclude, a spec's instance, a template's file.

### `scenario_files`

The `tastemaker.toml` that places a definition for a scenario whose project brings none, and the words its files are written with.

### `scenario_judging`

What a scenario's checked project found, judged against the findings it expects: each mismatch a problem.

### `scenario_proving`

What a definition's scenarios are proven with: the cover they give it, the workspaces they write and the problems of a definition that does not explain itself.

### scenarios

The scenarios a definition proves itself with: the files they start from and the findings they expect.

### scopes

Checks the counts, pairs and closed directories of the scopes a placement made.

### selectors

Resolves a selector list at one place and says what it matches.

### settings

What a caller sets on a request that writes: whether it writes, the values given by name, and the build that runs.

### `template_placing`

Places the files of every template entry, and finds the files a `rules-exclude` covers.

### topics

Answers the topics `explain` covers.

### variables

Puts each `{ variable = … }` of a file in place.

### writing

Says whether a command writes, or `-n/--dry-run` only says what it would write.
