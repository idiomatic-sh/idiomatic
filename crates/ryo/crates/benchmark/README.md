# idiomatic-sh-ryo-benchmark

Shared development harness for comparing Ryo with pinned linter defaults.

## Domains

### candidate_rules

Pure selection, dependency retention and declared rule configuration.

### canonical_text

The compact sorted-key document every pinned digest is taken over.

### corpus_discrepancy

A corpus comparison's differences are accepted only by finding, in accepted differences written for that corpus's digest.

### diagnostics

Canonical finding multisets retain duplicate occurrences, exact paths and byte locations.

### discrepancy

A pinned reference may differ from the intended contract only with complete, known and evidenced identities.

### input_metadata

Declared file observations are required and checked against the profile that pins them.

### inventory_comparison

Native execution evidence is compared under the declared comparison contract.

### inventory_receipts

Native case receipts are validated against the registered cases before any result counts.

### invocation_identity

Invocation spellings are normalized against the state boundary and request root, identically for captures and replay.

### measurements

Process observations separate measured wall time from decoded reports.

### observations

Executable observation dependencies are resolved from the authored declarations and the selected rules.

### process_failure

An explicit completed process failure binds its templates and its exact-binary archive group.

### process_output

Declared process output templates expand byte for byte, and a receipt identity is framed from its rule, case and side.

### process_receipts

A reference process receipt is rebuilt from registration and the actual request root, never from a passed flag alone.

### project_inputs

The optional project search roots and Given entry observations have one canonical identity for both contestants.

### registered_inputs

The declared inputs of a registered case, resolved the same way for registration and for its receipts.

### rule_context

Declared linter configuration is resolved, checked against the request and counted without matching paths.

### suite

Pinned profiles, authored cases and shared project inputs define the benchmark contract.
