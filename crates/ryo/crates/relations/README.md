# idiomatic-sh-ryo-relations

The portable relation catalog, its typed row and column schemas, closed term vocabulary, and typed absence causes. Language providers keep parsing, readers and file models. The common engine keeps acquisition, scheduling, storage, indexing, cache admission, invalidation and lifetime.

## Domains

### answers

The generic absence causes a language can report for a relation. Provider readers and sealed support answers remain in `ryo-language`.

### catalog

The one list of the relations ryo owns, with the optional capability a language promises each by, and the macro that declares a relation from its columns, its scope and whether it needs the languages' notes.

### declaration_kind

The closed set of abstractions every language maps its own declaration kinds onto.

### dependency_kind

The closed set of what a manifest dependency is: runtime, development, optional and the like.

### dependency_origin

The closed set of where a dependency's package comes from: a registry, a path, an archive and the like.

### elements

Where an element of a file comes from, the expressions embedded in it and the macro expansions that produced it.

### kinds

The hygienic numbering and naming macro for a provider's node and token kinds. Its generated types are relation contract types.

### labels

The names a relation is called and what it holds, as borrowed or static text.

### mapping_kind

The closed set of what a mapping in a manifest is.

### parameter_kind

The closed set of how a parameter is taken: positionally, by keyword and the like.

### relations

The exhaustive catalog of relations, typed columns and rows, optional capability declarations, and pure schema lookups.

### terms

Closed vocabularies and symbol identities used by relation cells and catalog metadata.

### value_kind

The closed set of what a value in a manifest is.
