# Engine extension contracts

This map records the code's current boundaries. It is an extension checklist, not a second architecture specification or a claim that every desired guard already exists. [The design](../README.md) remains the architectural source; the linked code and tests below establish current behavior.

**Engine** means the core use cases, domain algorithms, and outbound ports. **Provider** means a language or external adapter supplying source facts through a port. **Primitive** means one typed RyoQL operation and its domain evaluator. **Shared** means a result reused by more than one consumer under an explicit identity and lifetime; it does not mean process-global. **Partial** means facts may be missing and an empty answer is not proof of complete absence. **N/A** means that contract has no cache or mutable payload to manage. Status is **Current** when a named implementation and test enforce the stated boundary, **Partial** when a related mechanism exists but the complete desired guarantee is untested or distributed, and **Proposed** when it is design work awaiting integration. A status applies only to its row.

## Proposed primitive conformance gate

One core registration should bind an `OperationKind` to its evaluator, metadata schema, ordered inputs, absence dependency, feature entry, and public diagnostic cases. Keep the `Operation` enum as the serialized typed plan. Move only the shared dispatch and policy wiring into that registration; operation-specific schema and row algorithms remain with the primitive. A registration is complete only when an executable fixture checks:

1. A valid empty and populated input: schema equals compute output kinds, compute and stream produce the same ordered bag, including duplicates and zero rows.
2. Wrong variant, missing input, malformed column/kind, partial source, and failing emitter: exact error and first-emitted-prefix parity with the ordinary pipeline.
3. A public RyoQL compile/typecheck negative fixture and one valid pipeline/frontier fixture, so diagnostic mapping and scheduling cannot be skipped.
4. A counted `N` versus `2N` input where the primitive's declared traversal bound is checked by actual row visits and bounded retained cells; wall time is measured separately, not asserted in unit tests.

The existing [schema fixture](../../crates/core/src/domain/operation_schema/service_test.rs), [operator tests](../../crates/core/src/domain/operator/service_test.rs), [trust tests](../../crates/core/src/domain/trust/service_test.rs), and [query acceptance tests](../../crates/query_language/src/inbound/use_cases/compile/acceptance.rs) are starting material. The proposed gate needs a representative old primitive and the newer source span primitives before it can replace those separate obligations. It does not change provider or store APIs.

## Updating this map

When an extension changes a boundary, update its row in the same source change. Link the implementation and a behavior test or diagnostic receipt; mark an unintegrated patch **Proposed** and an untested guarantee **Partial**. Add a new row only for a genuinely new contract. Track remaining work under existing Beads issues where IDs exist; this page is not a second task ledger. Compare exact output and failure behavior before marking a new engine strategy **Current**, then record measured time and memory separately.
