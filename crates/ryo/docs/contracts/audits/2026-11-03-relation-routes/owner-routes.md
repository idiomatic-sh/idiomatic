## Confirmed host invalidation ambiguity (not a runtime regression run)

With the same two Text columns, row A `['x\ttext:y', 'z']` and row B `['x', 'y\ttext:z']` both become `text:x\ttext:y\ttext:z` in `core/domain/hosted/service.rs:31–41`. SDK `host_cell` accepts arbitrary Text (`sdk/.../lint/schemas.rs:456–460`); `table_of` interns the original cells directly, so parsing does not disallow or normalize the tab. `lint::stored_rules` digests `configuration(lines(hosted))` at `use_case.rs:394–396`. The entire HostedText vector can therefore be identical for changed valid row data. Host invalidation is **unchecked/blocked**, even if schema-only compilation identity is correct. This audit did not execute a cached-run regression and did not fix the encoder.
