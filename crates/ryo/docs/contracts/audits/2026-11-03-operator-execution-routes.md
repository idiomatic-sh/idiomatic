`G` = registered generic per-file collect/stream over admitted Stored, Selected, Computed or Tree inputs as accepted by the operation; `T` = terminal stream or retained cut; `X` = cross-file collected executor. `G/T` applies to 24 kinds: `Rows` and `Hosted` are assigned cross-file scope by the query planner. `X` has a registered dispatch entry for all 26, but a successful compiled-plan route depends on scope, frontier/step inputs, request sources, preflight and capability admission. The query lowerer refuses cross-file `SpanBetween`, `SourceMatches`, `RenderSyntax` and `FitsRendered`, so their `X` entries are **dispatch-only, compile-refused**. `Rows` and `Hosted` are **X only**. Any of the six manifest-provenance relations also forces its consuming step into cross-file scope: its producer hands over rows per file, but per-file G/T, K, L/LC, N, J and C consumption is N/A for that input. For other kinds, the planner can assign cross-file scope from cross-file inputs or file-origin key rules; `X` receives computed frontier/previous-step/hosted rows, not arbitrary direct native tree input. A missing required step returns `NotRun`, a missing relation handover returns an empty table, missing Hosted input returns `NotRun`, and uncertain partial inputs are filtered after evaluation. These are admission and failure routes, not successful semantic evidence. `K` = compact StoredSelection, only Select and Project from the exhaustive selector compiler. `L` = lowered tree position shapes for Select, Project, Join, Axis, Antijoin and Union; `LC` = GroupCount's separate lowered counting route. `N` = native ready Join or Axis only. `J` = application indexed ordinary/sparse Join only. `C` = fused Column chain: a final distinct Project from a Select with empty kept columns and a text filter, over a Join with empty filter/view whose left input is a kept step and right input is a catalog relation.
