# Independent architecture contract inventory audit (2026-11-03)

Read-only audit of `accepted/` (11dd1085, SIM-reviewed) and `extraction/` (ef0af73f on base f4151d18) against `boundary-proposal.md` (9a2abe39) and `matrix-proposal.md` (5b26737b). Checksums match identity.json. No build, no edits, no agents. Both trees untouched.

## Verdict: BLOCK

The proposed architecture is not adequate or complete as a boundary specification, and the extraction draft does not yet implement the nuhex pattern the user chose. Blocking facts, each source-grounded:

1. **Extraction is cut below the accepted head.** f415 is an ancestor of 11dd; the ten commits f415..11dd (487dc32e..11dd1085) add the whole keyed-semantic family: `ryo_language::domain::semantics` (`SemanticSession`, `RenderRequest/Outcome/Error/Context`), `LanguagePort::begin_semantics`, core `SemanticLookup` + `application/file_analysis/semantic.rs`, operators `RenderSyntax`/`FitsRendered`, the Python `semantic.rs` adapter, and `unicode-width`. None of it exists in extraction. The matrix row "Keyed semantic rendering demand" therefore describes code the draft cannot see. Operator counts differ: accepted `OperationKind` 26 / `QueryOperator` 25 / `OPERATORS` 25; extraction 24 / 23 / 23. The proposals' "all 24 operators" matches neither accepted count.
2. **Capability crate covers 2 of 26 primitive kinds.** `ryo_operators::OperatorCall` has `Project` and `Append` only (`crates/operators/src/domain/contract/types.rs`). Core `OperatorsItem` (26 impls, `pub(crate)`) stays in core; only project/extend/replace items call `lease.project/append`. `span_between::between` and `span_bounds::bounds` are `pub(crate)` modules unreachable from the inbound interface and unreferenced by core (dead under `dead_code = "deny"`; not built, so unverified). `SpanFault` is public and unused.
3. **Engine timing policy moved into a published capability crate.** `ModeContract`, `Publication`, `AcquisitionBoundary`, `SchemaBoundary`, `PreflightOrder`, `DemandOrder`, `SetScope`, `ResourceNeeds`, `Effects`, `InputShape`, `EvaluationMode`, `SourceGate` are now `pub` in `ryo_operators` and re-imported by core via `pub(crate) use` (`core/src/domain/operator/contract/types.rs:12`). The boundary proposal says scheduler/publication choices "stay internal". Publication timing, acquisition boundary and preflight order are engine policy, not portable row meaning.
4. **Pattern deviation at the adapter.** `OperatorsUseCaseAdapter::new()` constructs `OperatorsUseCaseImpl` itself and `factory::use_case()` takes no argument (`core/src/outbound/operators/{adapters/use_case/adapter.rs,factory.rs}`). Every existing cross-crate port is injected: `language::factory::use_case(handles)`, `query_language::factory::use_case(compile, typecheck)`, with the use-case impls built in SDK/CLI `composition.rs`. This is the "adapter constructs its dependency" shape earlier TM audits caught.
5. **Port fixtures do not follow the port spec.** Every other core port has `fixtures/{contract.rs,fake.rs,fake_test.rs}` under `cfg(any(test, feature = "fixtures"))`. The operators port has one `#[cfg(test)] fixtures.rs` returning the real adapter. `core-fakes`, `port/contract`, `fake`, `fake-test` templates are count=1 in `specs/port/0.2.0/spec.toml`; expect findings.
6. **Dependency direction is unenforced for the new crate.** Extraction's `tastemaker.toml` adds `crate-operators` and `nu-hex-operators` but leaves `crate-layers` unchanged; `layer-order` ignores a package no layer holds. "operators depends on language/values, never core" is currently guaranteed only by Cargo acyclicity.
7. **CLI composition not updated.** `LintUseCaseImpl::new` gained an `operators: Arc<dyn OperatorsPort>` parameter (14 args); `extraction/.../cli/src/resources/query/run/composition.rs:69` still passes 13. No cli file differs between trees. The snapshot cannot compile the CLI (structural, not built).
8. **Precondition inverted.** The matrix says to replace `InputSchema`, `ParameterBinding`, `OperatingError`, `PreparedInputs`, `PrimitiveLease`, `RowSink` with portable values "before any move". The extraction moved first and threaded the port through `PrimitiveLease.semantics` plus a second trait `PrimitiveSemantics` in domain and `PrimitiveSemanticsBridge` in application (`execution/lease.rs:24`). Workable bridge, but the semantic error vocabulary is wrong: `Append` returns `ProjectColumnAbsent` and core maps it to `WrongBinding`.

## Duplicate owners, cycles, leaks, generic vs provider

- **Duplicate owner (extraction):** `PrimitiveSemantics` (core domain) duplicates `OperatorsPort` (core outbound) to satisfy `import-directions` (domain may not name `crate::outbound`). Acceptable as a bridge only if documented as the single domain-side handle; otherwise it is a second interface for one capability.
- **Duplicate vocabulary:** `ProjectColumnAbsent` vs `RowsError::NoSuchColumn` vs `SpanFault::NoSuchColumn`; `OperatingError::WrongBinding` used to absorb an infallible `Append`. One semantic fault enum is needed.
- **Direction:** no Cargo cycle; `layer-order` layers do not include `operators`. Domain → `ryo_operators` is allowed (kernel-like crate) only if `ryo_operators` never depends on core; currently true by manifest.
- **Implementation leak:** engine timing enums public in `ryo_operators` (finding 3). `OperatorCall` uses fully qualified `ryo_language`/`ryo_values` paths in public fields: fine, these are kernel public types.
- **Implementation leak (accepted, pre-existing):** `ryo_core::application::{file_analysis::FileAnalysis, cross_file::CrossFile, rule_compilation::CompiledPlans}` are `pub` and constructed by SDK and CLI compositions. Constructor injection, not a locator, but it makes application services part of core's published API. `domain::{coverage,kind_check,corpus_copies}` are `pub` with no external user found in sdk/cli/benchmark.
- **Generic vs provider:** `LanguagePort::begin_semantics` and `ParseUseCase::{begin_semantics, completion_requirement, extend_file_model, recognizes_explicit}` carry default bodies. The ryo rule `no-default-trait-methods` is placed on `crates/language/src/**`; whether these are ratcheted findings was not verified (sampled asymptote locks show none). This is the mechanism by which optional provider capabilities are being added, and it contradicts the documented "adding a method breaks every language" contract. Decide: optional capability trait (separate, declared via `OptionalCapability`) vs default bodies.
- **Semantics of `Unsupported`:** three unrelated `Unsupported` meanings (file-level `FileReading::Unsupported`, `RenderOutcome::Unsupported(UnknownReason)`, parse errors). Already noted in the boundary proposal; unresolved.

## Stable portable API vs engine-owned policy (definition)

**Portable (pub, semver-gated through SDK or capability crates):** catalog relations and columns, `Value/CellKind/Span/NodeId/FileId/Symbol`, `Support/Reader/AbsenceCause/OptionalCapability/CompletionRequirement`, `Rows/Missing/ReadInPart/StoredPartial/Unknown/Unreadable`, plan meaning (`Operation`, `OperationKind`, `Input`, `ColumnIndex`, `Test`, `Comparison`), borrowed operator row calls plus one semantic fault enum, derived-view build/view over borrowed inputs (after `DerivedStorage/DerivedScratch/InputSchema/OperatingError` are replaced), `RenderRequest/RenderOutcome/RenderError/SemanticSession`, query program/grammar types.

**Engine-owned (`pub(crate)` in core, never a provider or capability contract):** `ModeContract` and its timing enums, `PrimitiveLease`, `RowSink`, `PredicateProgram`, `RelationOwner` admission/publication/release, `DerivedOwner`/`Ledger`/`graph_cache` budgets and reclamation, fanout decline policy, `CompiledPlans` cache identity, pipeline `run/deliver/keep/hand_over` and the five `evaluate_file_*` routes, scheduler/worker counts, memory budget, store framing and spill, digest/generation identity (`BuildIdentity`, `StoreSnapshot`, `FileAgain`), coverage-driven rule gating, `SemanticState` lifetime, route counts.

**Crate splits justified by a cohesive family:** at most `ryo-operators` (all 26 primitive row semantics with one fault enum; not the timing enums) and `ryo-derived` (12 derived kinds), and only after the stated precondition. No relation crate: catalog, answers, completion/readiness already live in `ryo-language` (domain + `application::completion`); what is missing is inventory rows and enforcement, not a crate. No store, reporting, or scheduler crates.

## Required Rust visibility and shared-TM constraints to box agents in

Rust/compiler (already active in `[workspace.lints]`: `dead_code = deny`, `private_interfaces = deny`, `unnameable_types = deny`, `unreachable_pub = warn`, `clippy::pub_use = deny`, `missing_docs = warn`):
1. Capability crate: `pub` only on `inbound::use_cases::<cap>::{interface,types,errors,use_case}` and `domain::contract::types`; every other domain module `pub(crate)`. Unreached items then fail `dead_code`, which prevents trait-per-helper sprawl.
2. Core: `outbound::<cap>::interface` names only capability public types; no `pub use` of capability types (`pub(crate) use` acceptable only if `no-reexports` does not flag it; unverified).
3. Core keeps `application::file_dag` and all `domain::*` `pub(crate)`; drop `pub` from `domain::{coverage,kind_check,corpus_copies}` unless an external user is named.
4. SDK gate: `workspace.metadata.api.allow` stays `ryo::resources::languages` only; `crates/sdk/api.txt` unchanged by any capability crate.
5. Cargo: capability `[dependencies]` = `ryo_language`, `ryo_values` only; `publish = true` implies the timing enums would be semver-locked, another reason to keep them in core.

Shared TM (existing rules, correctly placed, no new runner):
6. Add `operators` (and any `derived`) to `crate-layers`: `[["core"], ["query_language", "operators"], ["values"], ["language"]]` so `layer-order` sees it.
7. `nu-hex` + `port` spec already placed on the new crate/port: supply `fixtures/{contract.rs,fake.rs,fake_test.rs}` under `cfg(any(test, feature = "fixtures"))`, and `src/cases.rs` if the `crate` spec's `tested-by-cases` condition fires on `src/inbound.rs` (unverified).
8. `factory-calls`/`composition-wiring`: factory takes the capability impl; SDK/CLI `composition.rs` constructs `OperatorsUseCaseImpl::new()` and passes it, as for `CompileUseCaseImpl`.
9. Honest scope of TM: `layer-matrix`, `import-directions`, `derived-view-acquisition` compare resolved paths **within one crate** (`source-root = target-root`). Cross-crate owner access is enforced only by Rust visibility plus `layer-order` on manifests. A local-findings-clear result is not architecture proof for cross-crate ownership.
