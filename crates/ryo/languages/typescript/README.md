# idiomatic-sh-ryo-typescript

Ryo's TypeScript provider reads `.ts`, `.mts`, `.cts`, and `.tsx` through Oxc 0.142.0. JSX is enabled only for `.tsx`; ordinary TypeScript retains angle-bracket type assertions. Link it with `ryo_typescript::linked()`.

## Usage

Link the language with `ryo_typescript::linked()` and hand the result to the SDK's calls.

```rust
let language = ryo_typescript::linked();
assert_eq!(&*language.name().0, "typescript");
```

## Domains

### language

Recognizes file extensions and identifies the provider.

### nodes

Names the standard's node vocabulary.

### tokens

Names the standard's token vocabulary.

### extras

Names the source gaps the standard has no node or token for.

### syntax

Translates the vocabulary into engine kinds.

### names

Reads static names and decoded values from the syntax tree.

### scopes

Finds lexical owners in that tree.

### relations

Contains the source readers, one item per relation.

### packages

Holds the parsed npm package and TypeScript project declarations, with each configuration's `paths`, `baseUrl` and `extends`.

### manifests

Reads repository package dependencies, workspace membership, file ownership, the file each import names, and the files whose imports were examined.

### `fact_notes`

Notes the modules each file imports when it is parsed, for the project of the same run to read; the `notes` port writes them as postcard bytes and reads them back.

### links

Links each import to the file of the repository it names: relative specifiers, `paths` and `baseUrl` of the nearest project configuration and those it extends.

## Differences from the standard

The authority is `@typescript-eslint/ast-spec`, not the TypeScript compiler's distinct AST. Its node and token inventories are pinned under `tests/fixtures/standard`; independent trees are generated by `@typescript-eslint/typescript-estree` 8.72.0 with TypeScript 6.0.3. Runtime parsing uses Oxc's typed AST without an intermediate JSON serialization. Its parser wrappers are projected into the standard's tree, including binding annotations and parameter properties.

The element table adds whitespace and hashbang extras to preserve all source bytes, and expands the Program range to the entire file. Invalid input carries Oxc parser and early-syntax diagnostics; a reference-parser refusal requires a runtime diagnostic rather than an invented reference tree. Static relations report an unknown value for anonymous or dynamic names. They do not type-check, evaluate computed properties, or resolve imports through the TypeScript compiler.

`package.json` uses strict JSON; `tsconfig.json` permits comments and trailing commas. Workspace globs and package dependencies are resolved against the supplied repository manifests, a dependency no package of the repository answers being a row with no target, each with the origin its spec writes (`workspace:` a workspace member, `file:`, `link:` or a relative path a path, a git URL, a host's shorthand or `owner/repository` git, any other URL an archive's url, else the registry): the `workspaces` of `package.json` (npm, Yarn and Bun), and the `packages` of `pnpm-workspace.yaml`, which is YAML. Catalogs are read from `pnpm-workspace.yaml` (`catalog` and `catalogs`, see <https://pnpm.io/catalogs>) and from the root `package.json` of Bun (`catalog` and `catalogs`, at the top level or beside the workspace packages, see <https://bun.com/docs/pm/catalogs>); a dependency written `catalog:` or `catalog:<name>` takes the version the nearest enclosing workspace catalog gives it, and one no catalog answers draws no edge and is reported as a partial fact. TypeScript project references connect the packages of the referenced directories. Source dependencies and analyzed sources are read as `links` says; `paths` mappings are not package dependency rows.

## Reference regeneration

From this crate's directory, run `npm ci --prefix tests/fixtures/standard`, then regenerate `tests/fixtures/standard/output.txt` with its `dump.mjs` script over the `.ts` and `.tsx` files in `tests/fixtures/{relations,suite,corpus}`. The pinned npm lockfile records the independent parser versions. Runtime Rust dependencies are pinned by the workspace lockfile.
