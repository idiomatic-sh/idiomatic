# Uses of ordinary reads

`ordinary-read-uses(reads=<reference, file>)` gives the binding each given read uses: the binding `lookup-read-events` finds for it at stage 2, the read's own scope and then its enclosing scopes at the read's position. A read that resolves to a deletion, a cleanup or nothing uses no binding.

A function or lambda body is read after its enclosing scope, so its reads carry later positions and see that scope's final bindings without a rule of their own. The name lookup itself lives only in `lookup-read-events`: class scopes, handler-cleanup restoration, deletions and global/nonlocal homes are its rules. Callers pass the reads that are not deferred forward references, which resolve through `deferred-read-events`.

## Cost

A read resolves to its binding by one ordered pass, not by joining every read to every earlier binding. `latest-before(events=, probes=)` is the one definition of the latest event before a point: it pairs consecutive rows of each (scope, phase, name, file) group with `ordered-match`, then `resolve-pointers` follows each pointer to its fixed point in 20 doubling rounds, so a name with N bindings and N reads costs O(N), not O(N squared). The lookup also uses `resolve-pointers` for handler restoration: each `except ... as name` cleanup points at the latest event before the handler began, so a read after the handler resolves through the cleanup to the restored binding. F401, F841, F811 and F821 reach it through the lookup; F811, F821, F841 and F401 also use `latest-before` directly for their own per-name passes.

There is no fallback join. A chain of consecutive reads, or of restoring handlers, longer than 2^20 (1,048,576 events of one name in one scope between two bindings) would not reach its event in 20 rounds and would resolve to nothing; that is a source file of over 2 MB made of one name's reads, and each additional round costs one more join on every query that uses the fragment, which is why the count is not larger. The generated row `engine_test/lookup_linearity_test.rs` times F401, F841, F811 and F821 over every operation (bind, import, handler, annotation, delete, global, nonlocal, defaults, many functions reading a rebound name, a run of 16,384 reads and more) at 500 and 1,000 repetitions, with a doubling bound on time and on memory.
