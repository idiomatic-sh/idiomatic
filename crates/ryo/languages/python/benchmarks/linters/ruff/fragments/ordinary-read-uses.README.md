# Uses of ordinary reads

`ordinary-read-uses(reads=<reference, file>)` gives the binding each given read uses: the binding `lookup-read-events` finds for it at stage 2, the read's own scope and then its enclosing scopes at the read's position. A read that resolves to a deletion, a cleanup or nothing uses no binding.

A function or lambda body is read after its enclosing scope, so its reads carry later positions and see that scope's final bindings without a rule of their own. The name lookup itself lives only in `lookup-read-events`: class scopes, handler-cleanup restoration, deletions and global/nonlocal homes are its rules. Callers pass the reads that are not deferred forward references, which resolve through `deferred-read-events`.

## Cost

A read resolves to its binding by one ordered pass, not by joining every read to every earlier binding. `latest-before(events=, probes=)` is the one definition: it pairs consecutive rows of each (scope, phase, name, file) group with `ordered-match`, then follows each probe's pointer to the latest earlier event in 14 doubling rounds, so a name with N bindings and N reads costs O(N), not O(N squared). F401, F841, F811 and F821 reach it through the lookup; F811 also uses it directly to find, for each binding, the latest earlier use or deletion of its name.

A probe whose chain of consecutive probes is longer than 2^14 (a name read more than 16,384 times between two bindings of it in one scope) does not reach an event in 14 rounds. Those probes, and only those, take an exact fallback: they join the group's events that precede them and keep the latest. Its cost is the overflowing probes times the group's events; every such group needs a 16,384-read chain, so a file of N lines has at most N/16,384 events beside it and the fallback costs at most N squared over 16,384. The engine test `lookup_rules_cost_grows_with_the_file_not_its_square` times F401, F841, F811 and F821 over two file shapes at 1,000, 2,000 and 4,000 repetitions (doubling ratio at most 2.2) and reads one name 17,000 times to prove the fallback answers what a short chain does. Names bound by an `except ... as name` handler keep the join-based path for the reads inside the handler's span; their cost is bounded by the reads of that one name within the handler.
