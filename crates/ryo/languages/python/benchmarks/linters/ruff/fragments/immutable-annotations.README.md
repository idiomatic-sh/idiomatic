Models Ruff 0.16.5 `is_immutable_annotation` at parameter analysis time. The input is `checks(check:Node, root:Node, scope:Node, point:Number, file:File)`, where `check` is an actual caller AST node, `root` is the annotation expression, `scope` is the function/lambda being analyzed, and `point` is the final real binding-event ordinal visible in enclosing scopes. Output contains `check,file` exactly when the annotation is immutable under the upstream default catalog.

The current function's body has not run at this checker phase. Its parameters have been bound. Cached expression resolutions remain authoritative. Unvisited or unresolved heads look up the current namespace; this matters for postponed annotations and the original type of a stub NewType factory. Each caller has its own partition, so one factory expression can produce different results in functions with different parameter bindings. Real type-parameter declarations are namespace barriers, with ordinary closer values taking precedence.

Names imported from `builtins` retain import provenance. The upstream non-generic annotation catalog accepts implicit builtins, while its generic annotation catalog also accepts explicit `builtins` imports. Only prefixes of the finite upstream catalog are reconstructed for unvisited attributes. Two attribute transitions suffice because the catalog has at most three components; this is not a general-depth semantic-name resolver.

Optional, tuple-shaped Union, tuple-shaped nonempty Annotated, and BitOr recurse through their exact operands. Generic immutable annotations do not recurse into generic arguments. Every required reachable operand must qualify; empty Union tuples retain the upstream vacuous-all behavior. Source tokens identify BitOr, and every reported or contextual identity comes from the real AST.

The `lookup-symbol-events` stage 2 mode supports a caller context across multiple fresh expressions, skips the current function body namespace, and uses current active type-scope bindings, including class headers visited in the preceding deferred-class-base pass. The caller supplies current parameters and type-parameter barriers. It does not apply the stage 1 forward-deletion restoration policy used for deferred name reads. Existing stage 0 and 1 consumers keep their original behavior.
