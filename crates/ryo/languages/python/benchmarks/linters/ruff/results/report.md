## Architecture research and next steps

[Oxc's architecture](https://github.com/oxc-project/oxc/blob/d14dbd1e137de15a95d1d66417fbeea5cd2dd14e/ARCHITECTURE.md) shares arena-backed AST/infrastructure. [Oxlint's current type-aware backend](https://github.com/oxc-project/tsgolint/blob/9081583bd5c02c1b42bdebedf38e268fb68602c8/ARCHITECTURE.md) uses direct typescript-go AST, a shared Program, separate per-workload checkers and node-kind listeners. The Ryo hypothesis is to avoid repeated materialization while keeping shared immutable facts separate from mutable operation state; these source observations do not prove a speedup.

[tsrs defaults and fast mode](https://github.com/oxc-project/tsrs/blob/e18fb617ee516917342dcda27063ab67acc79e49/README.md) distinguish pinned checker behavior from adaptive counts/grouping/caches. Its [usage contract](https://github.com/oxc-project/tsrs/blob/e18fb617ee516917342dcda27063ab67acc79e49/docs/USAGE.md) makes lazy parsing and leaf freeing context-dependent, rejects incompatible history/lazy caches, and warns fast mode can change findings, locations, messages or exit status. Keeping strict options is not full diagnostic equivalence. Its [benchmark protocol](https://github.com/oxc-project/tsrs/blob/e18fb617ee516917342dcda27063ab67acc79e49/bench/README.md) pins projects/overlays, mostly enables fast explicitly, and measures default plus fast for releases. Ryo must pin mode, counts, order and cache lifetime and prove diagnostic equality.

The [October 20 announcement](https://blog.cloudflare.com/typescript-rust-port/) reported up to 8x and roughly 70% less memory against TypeScript 7.0 at equal checker counts; TypeScript 7.1 beta itself improved up to 2.5x. Those upstream results are not Ryo predictions. Current default/fast documentation supersedes the announcement's adaptive-default wording; tsrs/Oxlint integration was future exploration, not the current backend. Source commits, hashes, limitations and hypotheses are retained in the existing [research receipt](stored-key-index-targeted-2026-11-01.json).

Owner direction: application services should own cohesive operations and related structures with explicit lifetimes; use cases should remain readable orchestration allowed to call application, domain and outbound. The approved RuleCompilation/Tastemaker boundary batch now moves bounded compilation state into a cohesive application service and enforces sibling service boundaries; it preserves use-case access to domain and outbound contracts. Structural cache tests do not replace runtime cap/error/concurrency proofs. No refactor speedup is presumed, and the remaining missing query assets stay in scope.

A more concrete [Oxc dispatch implementation](https://github.com/oxc-project/oxc/blob/d14dbd1e137de15a95d1d66417fbeea5cd2dd14e/crates/oxc_linter/src/lib.rs) reuses per-thread RuleBuckets, visits semantic nodes once for registered node-kind and any-type rules, and runs run_once separately.
