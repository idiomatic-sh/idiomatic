# N999 deferred location contract

N999 remains in the existing `source_diagnostics` backlog. Filename/module
identity is available; the concrete missing contract is its diagnostic location.
Pinned Ruff 0.16.5 reports `TextRange::default()` (`0..0`), including nonempty
files. A minimal future fixture is `pkg/__init__.py = ""` alongside
`pkg/BadModule.py = "pass\n"`, with the diagnostic at `BadModule.py:0..0`.

Current findings require a typed `span` cell. For the nonempty file, actual token
and node endpoints include `0..4`, `4..5`, and EOF `5..5`; no existing span ends
at zero. `span-between` combines existing starts and ends, while query literals
cannot construct a span. Reusing the module or `pass` range would invent the
wrong location. An empty-file EOF span does not solve the nonempty case.

The follow-up is a generic validated point/span constructor or an explicit
file-level diagnostic location contract, not a Python- or Ruff-specific special
case. No implementation or capability/coverage claim is made by this note.

Source evidence: tagged
[`invalid_module_name.rs`](https://github.com/astral-sh/ruff/blob/0.16.5/crates/ruff_linter/src/rules/pep8_naming/rules/invalid_module_name.rs),
benchmark `diagnostic_findings` in `crates/benchmark/src/outbound/engine/adapters/local/adapter.rs`,
and core `span_between/item.rs`. The package identity and default ignore-name
policies must still be respected when the generic location contract is supplied.
