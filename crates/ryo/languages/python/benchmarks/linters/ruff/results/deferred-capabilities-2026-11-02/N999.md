- `invalid-syntax`: the incomplete relations are `comment` and `indent-region`,
  brought in by suppression's absence checks. `module-identity` is a Manifest
  relation and is not the source of uncertainty. Core `coverage/service.rs`
  marks every Lexical relation partial for `Recovery::SyntaxErrors`; Python's
  parser adapter currently excludes every lexical parser error from its
  `lexical_complete` classification even when byte/token coverage is otherwise
  complete. Inspect the exact EOF/error kind before refining generic lexical
  readiness. Fully observed comments and balanced INDENT/DEDENT regions may
  remain complete on syntax failure; unterminated strings/fstrings, invalid
  encoding, and genuinely truncated streams must remain partial. No N999-only
  bypass or fixture skip is appropriate.
- Explicit `.txt` and extensionless paths: candidate dispatch reports
  `NoLanguage`, while the pinned reference accepts the supplied empty fixtures.
  Those empty sources do not independently prove Python parsing. Prepared
  invalid-syntax controls will distinguish parse selection from simple ignoring.
  No existing language/provider override was found in SDK/core `LintRequest` or
  `FileToRead`. If explicit Python parsing is confirmed, the small shared
  contract is an optional, validated linked-provider hint at the inbound source
  boundary. Preserve original paths, validate the selected provider, and bind
  the choice into parse/cache identity. Do not add suffix heuristics or rename
  fixtures in the benchmark.
- `nested-dotted-initializer`: both saved pinned reference executions report no
  finding; the query reports the raw containing directory `inner.name`.
  Upstream uses `PackageRoot.path().file_name()` for initializer names. This is
  a policy-selection difference, not yet a proved reference bug. Independent
  execution of the unchanged original package layout, with valid-identifier
  and uppercase-style controls, is prepared to establish intended Python
  import/module-name behavior before changing either expectation. Retain the
  source and pinned expectation; use an explicit source-bound discrepancy only
  if that evidence warrants it.
