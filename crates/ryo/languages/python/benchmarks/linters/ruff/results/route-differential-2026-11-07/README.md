The differential of checkpoint 319 unwired each execution strategy alone and compared the reports byte for byte: the
tree join, the column kernel, the native positions and the stored selection answered like the wired engine within 1.3%
and are deleted; ordered existence is kept, because without it the 413-rule corpus run passed 23 GB resident. With one
path left there is nothing to unwire, so the test is now the canary of that path.

`results.json` holds the one row of the canary run: the workload, whether it failed, the report's SHA-256, its wall
seconds, CPU seconds and peak resident bytes.

`/tmp/ryo-event-ready-django213-20261105/cold-request.json`, with a fresh cache. The report must hold the diagnostics the
directional checkpoint recorded in `crates/ryo/docs/contracts/evidence/checkpoint/measurements.json`: 112, the whole
diagnostics list of the report, which is 110 N999 and the 2 `invalid-syntax` diagnostics of the frontend projection
(`tests/migrations/migrations_test_apps/with_generic_model/models.py` and
`tests/test_runner_apps/tagged/tests_syntax_error.py`). Pinned Ruff 0.16.5 reports the same 110 N999 files.

The test is `the_one_path_answers_the_django_canary_as_recorded` of the `ruff_sharing` target
(`cargo test -p idiomatic-sh-ryo-python --test ruff_sharing the_one_path`). It runs one configuration once in its
process, about 2 GB resident at checkpoint 319, so it runs in the validation set, as its own `ruff_canary` row: the
diagnostic-event subscriber `succeeds` installs is global to the process, so in one process the canary's events land
in `succeeds`' census.
