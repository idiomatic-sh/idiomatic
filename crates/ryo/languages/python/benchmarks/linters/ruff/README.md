# Ruff benchmark

Ruff 0.16.5 ships 413 selected rules. Each default is tracked as authored, explicitly deferred to an assessed capability issue, or still unassessed. An authored query becomes verified only after both contestants pass its independent cases. Deferrals never count as matches. The full audit refuses unassessed defaults; `measure-scoped` can produce explicitly interim evidence for the authored subset. The committed result artifacts identify the exact measured subset, source revision and collection method; they do not certify later source changes.

The latest completed combined snapshot is the immutable [310-rule PY310 r2 cohort](profiles/current-canonical-ready-310-r2/benchmark.toml): 6,411 of 6,553 full reports matched, with 142 mismatches and zero incomplete/error/Unknown candidates. Its [sealed aggregate](results/correctness-310-r2-final-2026-11-01.json) does not certify later query or provider changes. A new current combined cohort is being prepared; standalone migration equivalence is not combined parity. The older 205-rule/3,641-case run (2,210 exact, 1,427 mismatches and four incomplete UP025 cases) remains historical evidence in [its original directory](results/current-canonical-2026-11-01/) and [correctness.json](results/correctness.json). Full 413-rule parity and the current performance target remain unmet.

From `crates/ryo`, build the Python runner with `cargo build --release -p idiomatic-sh-ryo-python --bench ruff` and the collector with `cargo build --release -p idiomatic-sh-ryo-benchmark --bin ryo-benchmark-collector`. Cargo prints exact executable paths with `--message-format=json`. The runner accepts `audit`, `verify-tool /absolute/path/to/ruff`, `verify-cases /absolute/path/to/ruff`, `verify-reference-cases /absolute/path/to/ruff`, and `measure /absolute/path/to/ruff /absolute/path/to/cache /absolute/path/to/collector`. `verify-reference-cases` checks only the fixture expectations against pinned Ruff; it does not load or execute candidate queries and is not a candidate correctness certificate. Use `measure-valid` with those same three arguments for the fully accounted authored profile on syntactically valid inputs. The `measure` and `measure-valid` commands refuse pending or unassessed defaults. Use `measure-scoped-valid` with those arguments followed by `CODE1,CODE2` for an explicitly selected valid-source timing profile. The optional comma-separated final argument also selects the authored rules for `measure` and `measure-scoped`. Valid-source measurement retains full-input correctness refusals separately; it does not certify excluded sources. Measurement refuses a debug-profile executable.

The profile pins the Ruff executable hash, version, and tagged upstream default selectors. Projects and reversible patches belong to Python's benchmark directory, shared by future Python contestants. Each linter owns its command, output schema, settings, and RyoQL rules. Test cases use UTF-8 byte ranges. Missing tools, incomplete coverage, operational errors, unknowns, unread files and diagnostic differences are errors, never empty success.

When a rule query uses `semantic-child.ordinal`, remember it is a global child ordinal across all fields of the parent node, not a zero-based argument index. To identify the nth positional argument, rank only positional-argument siblings in source order; include fixtures where function and keyword children precede the argument so the distinction stays covered.

The shared process timer measures elapsed child wall time, including child spawn/wait, pipe collection, startup, SDK/query loading, compilation and output serialization. A small isolated collector process uses the pinned safe wait4 dependency to capture the contestant's user plus system CPU time and peak resident memory. Isolation prevents the large benchmark harness's resident memory from becoming the contestant's inherited RSS floor. The collector's own resident footprint remains a lower bound and is tested with a known-size child under a much larger harness. Peak RSS is the OS maximum resident set in KiB, converted to bytes. Collector startup, decoding, profile/executable certification and source hashing happen outside the child timer. The collector executable and exact SHA256 are frozen with the workload and checked before every invocation. BMF stdout reports medians and bounds for Asymptote; stderr retains individual observations and scope evidence. No performance result is implied by the existence of the instrumentation.

Empty-tool-cache, retained-tool-cache and edited runs are gated by exact diagnostic multisets, using six alternating-order trials and one processing worker per contestant. Every trial owns new cache directories; both edited contestants are compared with fresh-cache executions. OS page cache is uncontrolled, and retained caches do not imply verified cache hits. An immutable artifact snapshot seals the exact authored profile, queries, cases and both executable bytes. Every measured pair rechecks that seal and the source bytes. Both contestants receive the same explicit `.py`/`.pyi` files; other default-discovered formats are inventoried as exclusions linked to the frontend capability issue. This is Python-source subset evidence, not full default-discovery parity.


Candidate worker requests are staged as `request.json` inside that request's owned state directory and passed with `run-ryo --request-file <path>`. This avoids operating-system argument-size limits while preserving the exact JSON request bytes. The worker still accepts inline JSON for explicit debugging. `profile-ryo` writes a Chrome trace for a separate profiling invocation. `diagnostic-ryo --request-file <path> [python-target=3.10|python-target=3.11] <events.jsonl>` is a separate diagnostic command that writes flushed JSONL rule/file and pipeline-step start/end events to the explicit file; it does not produce timing evidence. Step durations are inclusive when one step runs another, and records include the parent step index. These diagnostics are opt-in, separate from timed workers. Set `RYO_DIAGNOSTIC_STEPS=0` for flushed rule/file events only; the default also records pipeline steps.

Current actual-proof asset admission uses `actual-proof-assets/v2`. It retains the
existing query/module byte identities and adds a pinned `phase_registry` asset
(`canonical_path`, `proof_sha256`). Each profile's normalized `settings` explicitly
binds `defaults`, `parser_configuration`, `project_context_mode`,
`rule_applicability`, and `flags` (currently `{}`). The verifier derives these from
the canonical profile and pinned Ruff phase registry and rejects unreviewed flags.
A complete report with a wrong phase, target or context cannot certify current
execution. Version 1 receipts remain historical evidence; missing settings are not
invented or promoted to current READY admission. Historical byte audits are explicit
and do not replace current v2 admission.
