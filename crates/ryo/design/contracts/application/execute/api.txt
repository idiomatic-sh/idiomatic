# The drafted public interface of application/execute, one public item per line, sorted within each group.
# Each line ends with two spaces and one tag: [main], [perf], [133], [changed: <what>] or [new].
# A quoted-from-code line carries @<rev>:<path>:<line> in the sheet, section 5; this listing carries only the tag.
# Paths are written flat (ryo_execute::Item), as the table, symbols and operators listings write theirs; the built crate
# keeps its nu-hex modules (inbound/use_cases/scan, outbound/project_tables, domain/answers).
# Owns: running a request's prepared programs over ONE file and handing that file's answers up, once.
# It does NOT prepare or bind programs (domain/programs), decide which programs can answer (application/screen, which it
# calls), say what an operator means (domain/operators, which it calls), spread files over workers (inbound/lint with
# outbound/scheduler), read bytes from disk (outbound/corpus), keep anything between runs (outbound/cache) or run the
# cross-file phase (application/project, which reads what this crate hands up).
# No layout word appears in any signature: `Table`, `cols`, `Rc<Table>`, `Vec<u64>`, `Box<[u64]>`, slot numbers,
# `World`, `Batch` and `Run` are absent on purpose (sheet section 9).
# Every line that names a type of ryo_table is UNPROVEN until domain/table/spike.md records a pass.
