# idiomatic-sh-ryo-describe  library ryo_describe
#
# The drafted public interface of inbound/describe, one public item per line, grouped and sorted within each group.
# Each line ends with two spaces and one tag: [main], [perf], [133], [changed: <what>] or [new].
# The quotes behind every tag are in sheet.md sections 2 to 5, each with @<rev>:<path>:<line>.
# Paths are written flat (ryo_describe::Item), as the table, symbols, ryoql, lint and validate listings write theirs; the
# built crate keeps its nu-hex modules (inbound/use_cases/{list_relations, describe_relation, list_operators,
# describe_operator}, domain/{relation_lookup, descriptions}).
# Owns: Ryo's catalog as a reader sees it: each relation (with what every linked language says of it) or operator,
# listed whole or described one at a time. It runs no rule, reads no file and is crossed once per request.
# It does NOT own the RyoQL grammar: `DescribeUseCase` stays domain/ryoql's and an edge composes it directly, as the
# SDK's `query::describe` does today (sheet decision 3). It does NOT own what an operator says of itself
# (domain/operators' `CatalogUseCase` and `OperatorDescription`) nor the relation catalog (domain/relations).
# No layout word appears in any signature. The one line that names a ryo_table type is marked UNPROVEN.
# STATUS: drafted 28 Nov. Not reviewed, not agreed.
# COUNT: 34 public items (4 traits, 4 trait methods, 4 structs and 4 constructors that build the use cases, 18 types and
# errors) plus 6 enum variants. Main and the tip each have 27 for the concept in core, plus the 7 relation description
# types and 2 functions in values::descriptions that move in (sheet section 5f). Of the 34: 15 as on main, 7 moved
# from values unchanged, 12 changed; none new.
