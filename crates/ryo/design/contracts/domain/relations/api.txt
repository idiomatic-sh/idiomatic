# idiomatic-sh-ryo-relations  library ryo_relations
#
# The drafted public interface of domain/relations, one public item per line, sorted within each group.
# Each line ends with two spaces and one tag: [main], [perf], [133], [changed: <what>] or [new].
# A quoted-from-code line carries @<rev>:<path>:<line> in the sheet, section 5; this listing carries only the tag.
# Paths are written flat (`ryo_relations::Relation`) as the table and symbols listings are; today every item sits under
# `ryo_relations::domain::{relations, catalog, terms, labels, answers, *_kind}::...`. The modules stay nu-hex inside.
# No layout word appears in any signature: `FactColumn`, `ColumnsView`, `Vec<u64>` and `Bits` are absent on purpose
# (sheet section 9; sheet decision 1).
# Types named from other sheets (never redefined here): ryo_table::{CellKind, CellWord, Count, KindBits, Offset,
# Position, PropertyId, FieldCode, ByteSpan} (domain/table/api.txt, UNPROVEN until domain/table/spike.md passes) and
# ryo_symbols::{Symbol, NameText, TextHash, NO_SYMBOL} (domain/symbols/api.txt).
# STATUS: drafted. Not agreed by the owner. Lines naming a ryo_table type are UNPROVEN until the table spike passes.
