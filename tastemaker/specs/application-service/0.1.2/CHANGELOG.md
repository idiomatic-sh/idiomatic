# application-service 0.1.2

Places the files of a nested part by their roles, where 0.1.1 placed only the operation's own top-level files and a product listed each nested file in its manifest. A nested part is a directory at any depth beneath the operation (`{*part}`): its module file `mod.rs`, its `service.rs`, `types.rs`, `constants.rs`, `errors.rs`, `interface.rs`, `schemas.rs` and `fixtures.rs`, its test support beneath `fixtures/`, its `test.rs` and `service_test.rs`, and its groups of cases `service_test/{*group}/` (`mod.rs`, `test.rs`, `fixtures.rs`); the operation's own test support beneath `fixtures/` and its own groups of cases are placed the same way. Every new entry has `count = { min = 0 }`. Each nested role is placed by its role's own template, as at the top, and the operation's role rules read the nested roles too (`{ placed-by = "part-errors" }` and the like), so a file that fails its role cannot pass by moving one directory down. A nested part's `mod.rs` declares the part's modules only, as the operation's own module file does (`test-group-namespace` with `case-table = "refused"`, entry `part-namespace`): its operation, data and failures go in its role files, held by those roles' rules. Scenarios `nested-part-is-placed` (nothing closed), `file-of-no-role-in-a-nested-part` (closed), `nested-part-module-holding-an-item` and `nested-part-errors-hold-the-errors-role` (refused) and `nested-part-errors-named-for-the-part` (passes).

The operation's `service_test.rs` is a case table or the namespace of its groups, placed by `test-group-module@0.2.0` and held by `test-group-namespace` with `case-table = "exempt"`, which holds a case table to the skeleton the `unit-test` template writes; scenario `service-and-test-of-an-operation` declares it. The spec-local `service-test` template, which nothing places any more, is removed. A group of the operation's cases, `service_test/{*group}/test.rs` (and a nested part's), is a `unit-test` with its own case rows and runners, read by `test-shape` as a test beside its source is; a group module is `test-group-module@0.2.0`, held by `test-group-namespace@0.1.0`, so a group that only gathers nested groups is a namespace. Its types follow `public-fields@0.3.0`. Scenarios `group-test-without-a-table`, `group-test-plain-scenario`, `nested-unit-test-without-cases`, `group-module-holding-a-test` (refused) and `group-namespace-module` (passes). Places `no-runtime-fixtures@0.2.0`, where 0.1.1 named its earlier version, so a product that places it locks one version of the rule. 0.1.1 is removed with this version, not kept as published: no lock names it, nothing has been released.
