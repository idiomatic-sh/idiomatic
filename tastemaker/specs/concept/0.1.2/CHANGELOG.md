# concept 0.1.2

Places the files of a nested part by their roles, as application-service 0.1.2 does for an operation, where 0.1.1 placed only the concept's own top-level files: a nested part at any depth (`{*part}`) with its `mod.rs`, its `service.rs`, `types.rs`, `constants.rs`, `errors.rs` and `fixtures.rs`, its test support beneath `fixtures/`, its `test.rs` and `service_test.rs`, and its groups of cases `service_test/{*group}/` (`mod.rs`, `test.rs`, `fixtures.rs`); the concept's own test support beneath `fixtures/` and its own groups of cases are placed the same way. Every new entry has `count = { min = 0 }`. Each nested role is placed by its role's own template and read by the concept's role rules, as at the top (`{ placed-by = "part-errors" }` and the like), so a file that fails its role cannot pass by moving one directory down. A nested part's `mod.rs` declares the part's modules only, as the concept's own module file does (`test-group-namespace` with `case-table = "refused"`, entry `part-namespace`): its functions, data and failures go in its role files, held by those roles' rules. A domain concept has no port and no IO at any depth: an `interface.rs` or a `schemas.rs` is a file of no role at the root and in a nested part alike. Scenarios `nested-part-is-placed` and `nested-part-module-declaring-its-roles` (pass), `file-of-no-role-in-a-nested-part`, `nested-part-port-and-schemas-are-closed` and `concept-with-interface` (closed), `nested-part-module-holding-an-item`, `nested-part-errors-hold-the-errors-role` (refused) and `nested-part-errors-named-for-the-part` (passes).

A concept's `service_test.rs` is a case table or the namespace of its groups (only `mod x;` declarations), placed by `test-group-module@0.2.0` and held by `test-group-namespace` with `case-table = "exempt"`, which holds a case table to the skeleton the `unit-test` template writes (`type Input`, `type Value`, `type Failure`, `const CASES: &[Case<Input, Value, Failure>]`, `fn subject`). Every group test, flat `service_test/{group}_test.rs` or directory `service_test/{*group}/test.rs`, is a `unit-test`, with its own case rows and runners, and `test-shape` reads it as it reads a test beside its source. Scenarios `flat-group-scenario`, `directory-group-scenario`, `directory-group-without-a-test`, `service-test-plain-test`, `service-test-case-table-without-subject` (refused) and `service-test-namespace-of-real-groups` (passes). Places `no-runtime-fixtures@0.2.0` and `public-fields@0.3.0`, where 0.1.1 named their earlier versions, so a product that places it locks one version of each rule. 0.1.1 is removed with this version, not kept as published: no lock names it, nothing has been released.
