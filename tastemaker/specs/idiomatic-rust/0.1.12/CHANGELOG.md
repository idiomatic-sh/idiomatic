# idiomatic-rust 0.1.12

`directions-domain` forbids a domain to name a use-case trait by any path: `*::inbound::use_cases::*::interface::*UseCase` and any path ending `UseCase` (an alias of the trait's module, `m::XUseCase`, or its parent, `metadata::interface::XUseCase`, and the bare name a glob brought in), the `interface` module itself (`use …::interface as m;`) and a glob of it (`use …::interface::*;`). What a domain needs from a use case is a port the domain declares, which its parent implements over the use case and hands down. The types and errors an interface module exports stay open, imported by name. `directions-root` forbids a crate's root modules (`src/*.rs`, `main.rs` aside) to name a use-case trait, so a root re-export under another name cannot carry one into a domain. An import's target is the item it names, so `*::interface` alone matched no import of the trait. Not resolved: a re-export under another name in a module other than the root that a domain may import, such as another domain file, which itself names the trait and is found there. Everything else is as in 0.1.11.
