# idiomatic-rust 0.1.13

`directions-domain` forbids a domain to name the SDK's re-exports of the parse and project traits, `ParseUseCase as Parse` and `ProjectUseCase as Project`, in these spellings: the full path (`ryo::languages::Parse`, imported or written in a signature), the path through the module the house style imports (`use ryo::languages;` then `languages::Parse`), and a glob of the module (`use ryo::languages::*;`), which would bring the traits in unnamed. The patterns are `languages::Parse`, `languages::Project`, `*::languages::Parse`, `*::languages::Project` and `*::languages::\*`. The types beside the traits (`languages::ParseRequest`, `languages::ProjectRequest`, …) and `use ryo::languages;` itself stay open. Not resolved: the module under another name (`use ryo::languages as l;` then `l::Parse`), because an import's target is `ryo::languages` whatever name it is bound to and a use through the alias is the unresolved path `l::Parse`, which a glob cannot tell from any other `x::Parse`; and the trait named bare after a glob, which the glob itself is found for. The SDK's `ryo::resources::languages::…` spelling is private to the SDK crate and unreachable from a provider. Everything else is as in 0.1.12, which forbids a domain to name a use-case trait by the paths `*::inbound::use_cases::*::interface::*UseCase` and any path ending `UseCase`, the `interface` module itself (`use …::interface as m;`) and a glob of it (`use …::interface::*;`), and `directions-root` forbids a crate's root modules (`src/*.rs`, `main.rs` aside) to name a use-case trait.
