# idiomatic-rust 0.1.13

`directions-domain` forbids a domain to name the SDK's re-exports of the parse and project traits, `ryo::languages::Parse` and `ryo::languages::Project` (`ParseUseCase as Parse`, `ProjectUseCase as Project`): the patterns `*::languages::Parse` and `*::languages::Project`, so an import, an aliased module path (`languages::Parse`) and a path in a signature are each found. The types beside them (`ParseRequest`, `ProjectRequest`, …) stay open. The SDK keeps these two names as the provider contract an adapter or a contract file implements; a domain does not. Everything else is as in 0.1.12, which forbids a domain to name a use-case trait by the paths `*::inbound::use_cases::*::interface::*UseCase` and any path ending `UseCase`, the `interface` module itself (`use …::interface as m;`) and a glob of it (`use …::interface::*;`), and `directions-root` forbids a crate's root modules (`src/*.rs`, `main.rs` aside) to name a use-case trait. Not resolved: a re-export under another name in a module other than the root that a domain may import, such as another domain file, which itself names the trait and is found there; the SDK's `ryo::resources::languages::…` spelling is private to the SDK crate and unreachable from a provider.
