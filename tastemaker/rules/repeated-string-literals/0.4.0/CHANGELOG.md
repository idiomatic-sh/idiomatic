# repeated-string-literals 0.4.0

A string written where the language admits only a literal is not a repeated literal: no constant can stand in for it, so the rule's advice cannot be followed. In Rust that is an attribute's arguments (`#[serde(rename_all = "kebab-case")]`, `#[deprecated = "…"]`, `stable_since = "v0.0.269"`), a `cfg` predicate (`feature = "schemars"`) and an ABI (`extern "system"`). The Rust provider's `string-literal` reads those strings decoded, as it reads every other string literal; the rule leaves out each row whose nearest `attr`, `cfg-atom` or `abi` ancestor in the syntax tree holds it, so the relation stays the one definition of a decoded string. Over ruff's source (`0be08a2`, scope `**/*.rs` without tests, benches and `build.rs`, `min-files = 5`), 0.3.0 would have reported 871 more rows once the provider reads these strings (feature names, serde arguments, version strings); 0.4.0 reports the same 3,081 rows 0.3.0 reported before. Scenarios `attribute-arguments-five-files`, `attribute-value-three-files` and `cfg-and-abi-three-files` (no finding) and `literal-beside-attribute-three-files` (the expressions beside the attributes are still reported); the 0.3.0 scenarios hold unchanged. Everything else is as in 0.3.0. 0.3.0 is removed with this version, not kept as published: no lock names it once every spec ryo places names 0.4.0, nothing has been released, and an unreleased version keeps no copy for compatibility.

## 0.3.0

A value that is one lower-case word is not a repeated literal. 0.2.0 reported `source`, `reference`, `candidate`, `running` or `failed` once three `constants.rs` or `schemas.rs` files of different crates each named a column, key or state of their own format with the same word, although no crate can name another's constant. `constants-once` already treats such a word as a format's vocabulary; this rule now does too. The query keeps only the literals that hold a character outside `a-z`. A longer or multi-word value (`two words`, `Source1`, `cases.jsonl`) is still reported, and the scenarios prove both sides.
