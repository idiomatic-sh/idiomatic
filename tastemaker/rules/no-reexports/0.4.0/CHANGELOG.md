# no-reexports 0.4.0

Allow one unrenamed private `domain/<concept>/types` signature item per public use in a canonical inbound use-case interface. Grouped imports, sibling locations and implementation-service paths remain forbidden. This is a syntax placement rule; Rust visibility and real public-API tests prove callable authority.

The passing signature scenario declares its nominal target types. Placed concept rules separately reject functions, aliases and inherent owner constructors in `types.rs`; this rule alone does not resolve target declarations.

Edited in place: the canonical inbound interface may forward the private domain `*/errors` a signature carries beside the `*/types` it already could; the fixtures state the accepted error and the application module that still cannot.
