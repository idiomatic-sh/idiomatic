# no-reexports 0.6.0

One seam that 0.5.0 reported as a re-export is not: a use case's `interface.rs` may forward an outbound port trait when the signature of an entry trait the interface declares or forwards names it, since a caller hands the port in and must name it (ryo's execution interface and its observer and facts ports). A `pub use` in a fixtures module, gated or not, a port no entry signature names, an adapter, and a forward from any file but the interface are still refused. Scenarios `use-case-forwards-a-port-its-entry-names` (pass), `gated-fixtures-module-forwards-vocabulary`, `ungated-fixtures-module-forward`, `gated-non-fixtures-module-forward`, `use-case-forwards-a-port-no-entry-names`, `use-case-forwards-an-adapter` and `port-forwarded-from-a-use-case-body` (refused). Everything else is as in 0.5.0, which is removed with this version: no lock names it, nothing has been released.

Edited in place: the port seam is keyed on the forwarding file. A port is forwarded only by an `interface.rs` one of whose own entry traits, declared there or forwarded from there, names it; a port a sibling use case's entry names is still refused in an interface whose own entries do not. Scenario `use-case-forwards-a-port-only-a-sibling-names`.

# no-reexports 0.5.0

A canonical inbound use-case interface may also forward, one unrenamed item per public use, an application or domain type or trait of its crate, declared anywhere beneath `application/` or `domain/`, that its contract is made of: one the signature of one of the interface's methods names, or one that a type so named names in its fields, variants or methods, or one that such a type implements or is implemented by, transitively. The handles a use case returns and the protocol traits they implement are part of its contract. The fixtures state the accepted handle, its parts, its protocol trait and a sealed domain value it holds; an application type no signature reaches, an application service function and a sibling application module's forward stay refused. Everything else is as in 0.4.0.

The `internal-crates` param names the crates a product splits its own domain or application into beneath the crate whose interfaces forward them (ryo's engine domain crate below execution): a forwarded path rooted at one of them counts as the crate's own, as a `crate::` path does. The fixtures state an admitted forward from a named crate and a refused one from a crate the param does not name.

Edited in place: a `pub use` inside a gated `fixtures` module is a re-export again. Its one user forwarded a type a test can import from its defining public module; a test imports the item where it is defined, as every consumer does. Scenario `gated-fixtures-module-forwards-vocabulary` is reported.
