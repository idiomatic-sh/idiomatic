# test-shape 0.2.0

A new required param `reads` says which test files an entry holds to the runner shape: `every-test` (as 0.1.0 did, for a test beside one source file) or `case-tables`, only a file that declares a `CASES` table. A group test is one of two forms chosen by that one mechanical fact: a case table, held to the shape, or plain `#[test]` scenarios under `scenario-test`. Scenarios `case-tables-only-reads-a-case-table` and `case-tables-only-leaves-a-scenario`; the 0.1.0 scenarios hold with `reads = "every-test"`.

Edited in place: with `reads = "case-tables"` a file that declares `CASES` also holds the table's skeleton, as the `unit-test` template writes it: `type Input`, `type Value`, `type Failure`, `const CASES: &[Case<Input, Value, Failure>]` and `fn subject`, each missing piece and an untyped table reported at the table. A proof that is a case table or the namespace of its groups (`service_test.rs`, `adapter_test.rs`) is placed by `test-group-module`, whose template is one doc line, so the case-table form kept its skeleton only through this entry. The finding's message now says which of the two it is. Scenarios `case-tables-holds-the-skeleton` and `case-tables-holds-the-typed-table`; `case-tables-only-reads-a-case-table` holds a full skeleton so that it isolates the runner.
