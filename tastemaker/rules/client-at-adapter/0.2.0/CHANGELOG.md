# client-at-adapter 0.2.0

Where a client library may be named is read by the rule, not by its entry's excludes: a file the adapter spec places (as in 0.1.0), any file beneath an outbound port's `adapters/` (`**/outbound/*/adapters/**`, placed by any spec), a port's `**/outbound/*/factory.rs` and an edge's `**/composition.rs`. 0.1.0 counted only the adapter spec's own roles and left factory.rs and composition.rs to the entry's `exclude`, so a language crate, whose adapters its own spec places, excluded `**/adapters/**` in its manifest, a carve-out. An entry now reads `**` with no exclude, and fixtures and tests are read: the contract (a client only in an adapter, a factory, a composition) covers them. Scenario `unplaced-adapter-tree-names-client-library`: the language adapter, the factory and the composition pass; the domain and `src/fixtures/x.rs` are reported. Everything else is as in 0.1.0, which stays as published: tastemaker and asymptote lock it.

Edited in place: the `[given]` reads `**` with no exclude, and the `domain-test` and `adapter-test` scenarios carry none, so the adapter test passes by the query and the domain test is reported by it; the description names factory.rs and composition.rs once.

Edited in place: an edge's composition is one the specs place, `**/src/resources/*/*/composition.rs` (a command's or an SDK entry's), `**/src/inbound/contracts/**/composition.rs` (a language contract's and its readers'), `**/benchmarks/linters/*/composition.rs` and `**/benches/**/composition.rs` (benchmark hosts), not a `composition.rs` in any directory: a domain `composition.rs` that names a client is reported. Tests and fixtures stay out of an entry by its explicit test-role excludes, as idiomatic-rust places the rule: tests set a scene up with any library (PM ruling, 2026-11-11).
