# no-language-names 0.4.0

One string 0.3.0 reported names no language and assumes none: `.git`, the version-control directory a core skips, is no file extension. It was a finding with no language in it, and the only way past was an ignore. Every other check is as in 0.3.0: language names as whole words, the bare extensions of a core, and the source files, build manifests and module paths a string assumes (`src/lib.rs`, `main.py`, `Cargo.toml`, `go.mod`, `package.json`, `crate::`); a path beneath a repository's `tools/`, in a remedy that runs an installer or alone, is a source path like any other (the rule holds no one repository's command: a v1 product that prints one carries an in-source ignore with its reason). Scenarios `version-control-directory-is-no-extension`, `repository-tool-path-is-a-source-path` (reported) and `string-holds-a-language-name-as-a-word` (reported).
