# no-language-names 0.4.0

Two strings 0.3.0 reported name no language and assume none: `.git`, the version-control directory a core skips, is no file extension; and a remedy that runs the repository's own installer, written exactly `uv run --script tools/install.py`, names that one file of the repository, not a file of the user's; the path anywhere else, and a file beneath any other `tools/` (`x/tools/main.py`), is still reported. Each was a finding with no language in it, and the only way past was an ignore. Every other check is as in 0.3.0: language names as whole words, the bare extensions of a core, and the source files, build manifests and module paths a string assumes (`src/lib.rs`, `main.py`, `Cargo.toml`, `go.mod`, `package.json`, `crate::`). Scenarios `version-control-directory-is-no-extension` and `repository-tool-path-assumes-no-language` (the remedy passes; a bare `tools/install.py`, `x/tools/main.py` and `main.py` are still reported), and `string-holds-a-language-name-as-a-word` (reported).
